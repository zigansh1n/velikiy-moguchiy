# «Великий & Могучий» для macOS

Диктовка в строке меню: нажали клавишу, говорите, отпустили — распознанный (и, если хотите, исправленный LLM)
текст вставляется туда, где стоит курсор, в любом приложении.
Обзор всего проекта, конфиденциальность и лицензии — в [корневом README](../README.md).

## Установка готовой сборки

Нужен Mac на Apple Silicon с macOS 14 или новее.

1. Скачайте `VelikiyMoguchiy-macOS-arm64.zip` со страницы
   [Releases](https://github.com/zigansh1n/velikiy-moguchiy/releases), распакуйте и перенесите
   `VelikiyMoguchiy.app` в «Программы».
2. Сборка **не подписана сертификатом Apple** (подпись — собственным сертификатом проекта), поэтому Gatekeeper
   при первом запуске её не откроет. Либо: «Системные настройки → Конфиденциальность и безопасность» → внизу
   «Всё равно открыть»; либо в Терминале снимите карантин:

   ```bash
   xattr -dr com.apple.quarantine /Applications/VelikiyMoguchiy.app
   ```

3. При первом запуске откроется окно «Начало работы» (потом — из меню значка): дайте доступ к **микрофону**,
   **универсальному доступу** и **мониторингу ввода** (таблица ниже), затем в настройках укажите ключ провайдера
   распознавания (для русского — DashScope, модели Qwen; как его получить — [`docs/DASHSCOPE-KEY.md`](../docs/DASHSCOPE-KEY.md))
   и нажмите «Проверить ключ».
   Нет ключа — приложение предложит распознавать речь прямо на Mac: русская модель Vosk (около 30 МБ, sherpa-onnx)
   скачается один раз с проверкой SHA-256, звук никуда не уходит. Ключ можно указать позже; приложение никогда не
   меняет выбранное распознавание само, если ключ задан. После «Не сейчас» предложение больше не появляется, а
   локальную модель можно выбрать в настройках распознавания.

Сборки подписаны одним и тем же сертификатом проекта «Velikiy Moguchiy Release» (открытая часть —
[`scripts/release-signing-certificate.crt`](scripts/release-signing-certificate.crt)), и macOS сохраняет выданные
разрешения при обновлении. Раньше сборки были подписаны ad hoc, поэтому **один раз**, после установки первой версии
с постоянной подписью, разрешения нужно выдать заново: в «Конфиденциальность и безопасность» удалите
VelikiyMoguchiy кнопкой «−» из списков «Универсальный доступ» и «Мониторинг ввода» (просто поставить галочку не
выйдет: macOS её снимет, пока в списке старая запись), запустите приложение и дайте доступ снова; доступ к
микрофону macOS спросит сама. Сбросить старую запись умеет и само приложение — кнопка «Исправить», см.
[«Разрешение не включается / сбрасывается»](#разрешение-не-включается--сбрасывается). После этого обновления разрешения не сбрасывают. Сборки форков, собранные без сертификата проекта,
подписаны ad hoc и теряют разрешения при каждом обновлении. Проверить подпись:
`codesign -d -r- /Applications/VelikiyMoguchiy.app` — в ответе должно быть `certificate leaf`.

Автообновления нет, пока у проекта нет Developer ID: раз в день приложение
проверяет [Releases](https://github.com/zigansh1n/velikiy-moguchiy/releases) и, если вышла новая версия, показывает
в меню «Доступна новая версия …» со ссылкой. Скачивает и ставит её пользователь.

## Сборка из исходников

Нужны Xcode, Rust (`rustup`), `cmake` и [XcodeGen](https://github.com/yonaskolb/XcodeGen):
`brew install cmake xcodegen`.

```bash
git clone https://github.com/zigansh1n/velikiy-moguchiy.git
cd velikiy-moguchiy/mac
cp MacApp/Config/Secrets.xcconfig.example MacApp/Config/Secrets.xcconfig   # по желанию: свой bundle id для форка
bash scripts/setup-codesign-identity.sh   # по желанию, один раз: разрешения не слетают между сборками
make build          # XcodeGen + ядро на Rust + приложение + встроенный CLI
make install-app    # копирует VelikiyMoguchiy.app в /Applications
```

Своя сборка подписана другим сертификатом, чем сборки из Releases, поэтому при переходе между ними разрешения
снова придётся выдать заново.

Только ядро и его тесты: `cargo test --workspace` в этой папке. CI собирает приложение так же
(`.github/workflows/build-apple.yml` в корне репозитория). Логика приложения (без интерфейса):
`xcodebuild test -project MacApp/VelikiyMoguchiy.xcodeproj -scheme VelikiyMoguchiyLogicTests`.

Bundle id сборок — `io.github.zigansh1n.velikiy-moguchiy` (`MacApp/Config/Base.xcconfig`); к нему macOS привязывает
разрешения и настройки. Форку лучше задать свой в `MacApp/Config/Secrets.xcconfig` (файл не попадает в git).

## Разрешения

| Разрешение | Зачем | Без него |
|---|---|---|
| Микрофон | запись речи | запись не начнётся |
| Универсальный доступ | вставка текста (имитация `Cmd+V`) | текст остаётся в буфере обмена, вставлять вручную |
| Мониторинг ввода | глобальная клавиша диктовки (по умолчанию **Fn**) | клавиша не срабатывает |
| Распознавание речи | только для провайдера Apple Speech (macOS 26+) | остальные провайдеры работают |
| Камера | только «Снимать камеру во время диктовки» («Управление → Губы») и экспериментальный режим «губы»; оба по умолчанию выключены | ничего не меняется |

### Разрешение не включается / сбрасывается

Переключатель у «Великого & Могучего» стоит, а вставка или клавиша не работают; включаете заново, а он
снова выключается. Так бывает после обновления со старой сборки: macOS хранит разрешение для прежней
подписи приложения и не даёт его этой. Тогда в меню приложения появляется «Доступ к управлению не работает —
исправить» (или «Мониторинг ввода не работает — исправить»), и при вставке без доступа приходит такое же
уведомление. Кнопка «Исправить» сбрасывает только строку «Великого & Могучего» в этом списке разрешений
(`tccutil reset Accessibility io.github.zigansh1n.velikiy-moguchiy`, для мониторинга ввода — `ListenEvent`),
больше ничего не удаляется, и открывает нужный раздел Системных настроек. Включите переключатель заново:
приложение подхватит доступ без перезапуска. Само, без нажатия кнопки, приложение ничего не сбрасывает.

## Данные и настройки

Настройки, ключи, история, записи диктовок и модели лежат в `~/.velikiy-moguchiy/` (`config.yaml`, `dictionary.txt`,
`history.db`, `recordings/`, промпты; полный список ниже). Если остался только каталог `~/.koe/` от сборок до
переименования, приложение продолжает работать с ним. Файл `config.yaml` создаётся при первом запуске,
с комментариями к полям.

Что и куда отправляется, — в [PRIVACY.md](../PRIVACY.md). Сторонние лицензии — в [THIRD_PARTY.md](THIRD_PARTY.md)
и в окне «О программе → Лицензии».

## Как это работает

1. Нажмите клавишу диктовки (по умолчанию **Fn**). Режимы (`hotkey.trigger_mode`): `hold` — держите, пока
   говорите; `toggle` — нажали, чтобы начать, и ещё раз, чтобы закончить; `double_tap` — двойное нажатие
   начинает, одиночное заканчивает. Клавишу можно сменить на Option, Command, Control, код клавиши или сочетание.
2. Звук в реальном времени уходит провайдеру распознавания с вашим ключом (для русского — Qwen через DashScope)
   или остаётся на Mac с локальным провайдером.
3. Плашка внизу экрана показывает, что идёт запись, а затем распознавание; текст диктовки в ней не выводится.
   Короткая подпись рядом говорит, чем всё кончилось («Скопировано», «Отменено», причина ошибки), а ответ на
   вопрос, невставленный перевод и что делать при ошибке открываются в карточке над плашкой.
4. Итоговый текст вставляется в активное поле ввода.

Ещё две клавиши работают так же, как клавиша диктовки (в новых конфигах): **правый ⌥** — перевод сказанного на
язык `asr.qwen.translate_to`, **левый Control** — вопрос по выделенному тексту. Им нужен ключ DashScope: без него
клавиша так и скажет. Клавиши «отменить вставку» и «вставить последнюю диктовку» срабатывают от двойного нажатия.

Провайдеры:

- **облачные:** Qwen (DashScope), Doubao, GLM, MiMo по вашему ключу;
- **ChatGPT (ваша подписка) — неофициально:** без ключа API, через вход в ваш аккаунт ChatGPT (как в Codex) и
  внутренний адрес голосового ввода приложений ChatGPT. Звук уходит в OpenAI одним файлом после конца записи. OpenAI
  может изменить этот адрес в любой момент, и тогда способ перестанет работать; перед первым выбором приложение
  предупреждает об этом. Подходит и бесплатный аккаунт. Расшифровка не тратит сообщения чата, но у голосового ввода
  OpenAI есть свой лимит, размер которого не публикуется; когда он закончится, приложение скажет об этом и по нажатию
  на уведомление вернёт прежнюю модель. Вход хранится в связке ключей, «Проверить» отправляет секунду тишины;
- **локальные:** Apple Speech (macOS 26+, без ключа), MLX (модели Qwen3-ASR на Apple Silicon), sherpa-onnx (CPU),
  whisper.cpp (модели Whisper в формате ggml, на видеокарте Mac через Metal);
- **LLM для исправления:** OpenAI Chat Completions и Responses, Anthropic Messages, совместимые шлюзы, локальные
  модели MLX.

### Расшифровка файлов

Голосовое из Telegram или WhatsApp (`.ogg`, `.oga`, `.opus`), запись встречи, подкаст или видео можно перетащить на
значок в строке меню, выбрать в меню «Расшифровать файл…» или в Finder: правый клик → «Службы» → «Расшифровать в
Великий & Могучий». Файл распознаёт провайдер, выбранный в настройках: облачный или локальный, в том числе без сети.
Звук режется по паузам на куски не длиннее 20 секунд. Это нужно сервисам с ограничением длины запроса, и из этих же
кусков получаются субтитры. Тихие куски не отправляются никуда. В окне видно, сколько частей уже распознано; потом
появляется текст, его можно поправить, скопировать, сохранить как `.txt` или сохранить субтитры `.srt`. Голосовые Ogg
Opus читает само приложение, остальное — macOS (AVFoundation), ffmpeg не нужен. Исправление LLM, голосовые команды и
сниппеты к файлам не применяются, а в историю диктовок файлы не попадают.

## Файлы в `~/.velikiy-moguchiy/`

| Файл | Что в нём |
|---|---|
| `config.yaml` | основные настройки: распознавание, LLM, звуки, клавиша, словарь |
| `config.yaml.bak` | копия `config.yaml` до последнего сохранения настроек |
| `dictionary.txt` | словарь: строка `Правильно \| как произносят` (вторая часть необязательна), `#` — комментарий; с Qwen Omni уходит в каждую диктовку (до 120 записей и 2500 знаков вместе со встроенным), с другими моделями — подсказками распознаванию и в LLM |
| `system_prompt.txt` | правила исправления текста для LLM |
| `user_prompt.txt` | шаблон запроса к LLM; подстановки `{{asr_text}}`, `{{interim_history}}`, `{{dictionary_entries}}` |
| `dictionary-it-ru.txt` | встроенный словарь IT-терминов и брендов, копируется из приложения; выключается `dictionary.starter_enabled: false` («Настройки → Словарь») |
| `history.db` | история и статистика диктовок (SQLite) |
| `recordings/` | звук каждой диктовки (AAC, `.m4a`), включая отменённые и неудачные; по умолчанию включено (`history.save_recordings`), записи старше 30 дней удаляются (`history.recordings_retention_days`) |
| `lipdata/voiced/` | видео с камеры и распознанный текст диктовок, только если включено `lipdata.capture_video` (по умолчанию выключено) |
| `lips_training/` | состояние и результаты «Обучить на мне», если вы его запускали |
| `models/` | локальные модели; у каждой папки файл `.koe-manifest.json` со списком файлов и их sha256; скачанные с Hugging Face — в `models/hf/`, подключённые «на месте» — только описание в `models/external/` |

Большую часть этого можно править в окне настроек (из меню в строке меню). Если файла промпта нет или он пустой,
используется встроенный текст из `velikiy-moguchiy-core`; существующий `user_prompt.txt` приложение не перезаписывает.

## Режим «губы» (эксперимент)

Включается в `config.yaml`: `experimental.lips: true` и клавиша `hotkey.lips_key`. При первом нажатии клавиши
приложение объясняет, что скачает, и после согласия ставит всё само, с прогрессом и кнопкой «Отменить» (загрузка
продолжается с того же места). После «Не сейчас» клавиша только напоминает, а установить можно в «Настройки →
Управление → Губы → Режим «губы»». Что ставится:

- базовая модель MultiVSR у её авторов (Оксфорд, около 4,5 ГБ; её лицензия не указана, поэтому в проекте её нет);
- дообученная модель губ, самая новая из [Hugging Face](https://huggingface.co/z1gansh1n/velikiy-moguchiy-lips) и
  выпусков `lips-*` [velikiy-moguchiy-models](https://github.com/zigansh1n/velikiy-moguchiy-models/releases): сначала с
  Hugging Face, если он недоступен — с GitHub;
- [uv](https://github.com/astral-sh/uv), Python 3.13 и библиотеки из `lipread/uv.lock` (по хэшам из lock-файла,
  ffmpeg — пакет `imageio-ffmpeg`), код MultiVSR на закреплённом коммите.

Проверки: у моделей — SHA-256 из `SHA256SUMS.txt`, сверенные с хэшами Hugging Face и GitHub; выпуски новее
`lips-0.1` должны быть подписаны ключом проекта (`SHA256SUMS.txt.sig`, Ed25519, открытый ключ встроен в приложение;
подписать — `tools/models/sign_lips_release.py`); у базовой модели — закреплённый SHA-256; код MultiVSR сверяется
пофайлово с `lipread/multivsr_files.sha256`, потому что архивы GitHub не гарантируют одинаковых байтов. Свои
чекпойнты сервис загружает только как тензоры (`weights_only=True`).

Всё лежит в `~/.velikiy-moguchiy/`: модели — в `models/lips/`, окружение сервиса — в `lips/` (журнал установки —
`lips/setup.log`). Код сервиса берётся из самого приложения. Раз в день приложение проверяет, нет ли модели новее, и
предлагает обновить её из меню.

Разработчику загрузка не нужна: приложение, собранное из исходников (`make build`), запускает сервис из папки
`lipread/` этого же репозитория, если в ней есть `.venv` (`lipread/setup.sh`). Другую папку задаёт
`lips.service_dir`. Сборки из CI этого пути не знают.

## Сообщить о проблеме

Пункт меню «Сообщить о проблеме…» собирает версию приложения, версию macOS и последние строки лога этого запуска,
скрывает ключи, токены, почту, тексты диктовок и имя пользователя в путях и показывает всё это: текст можно
поправить. Ничего не отправляется само: «Открыть на GitHub» открывает в браузере заполненную форму
[«Сообщить о проблеме»](https://github.com/zigansh1n/velikiy-moguchiy/issues/new?template=problem.yml), её
отправляете вы.

## Командная строка и локальные модели

Внутри приложения лежит CLI `velikiy-moguchiy` (`Contents/MacOS/velikiy-moguchiy-cli`; `make build` ставит и его):

```bash
velikiy-moguchiy model list                              # какие модели есть и в каком они состоянии
velikiy-moguchiy model pull mlx/Qwen3-ASR-0.6B-4bit      # скачать (с проверкой sha256)
velikiy-moguchiy model status mlx/Qwen3-ASR-0.6B-4bit
velikiy-moguchiy model remove mlx/Qwen3-ASR-0.6B-4bit    # удалить файлы, манифест остаётся
velikiy-moguchiy transcribe голосовое.ogg -i               # текст файла, с ходом работы
velikiy-moguchiy transcribe лекция.mp4 --format srt > лекция.srt   # субтитры (или --format json)
```

`transcribe` читает Ogg Opus и WAV 16 кГц сам, остальные форматы — через ffmpeg. CLI внутри приложения собран без
локальных провайдеров (sherpa-onnx, Apple Speech); расшифровка из меню их поддерживает.

Скачать модель можно и в настройках, на вкладке распознавания. Если и распознавание, и LLM локальные (MLX), приложение
работает совсем без сети.

## Модели распознавания

«Настройки → Распознавание → Модели…» открывают окно с четырьмя вкладками. Распознавание само на другую модель не
переключается: только по кнопке «Сделать основной».

- **Рекомендуемые** — модели, которые мы проверили для русской речи (список — `velikiy-moguchiy-core/src/hf_models/recommended.json`,
  правится без кода). У каждой: движок, размер, качество, скорость, языки, лицензия. «Скачать» показывает прогресс,
  скорость и оставшееся время прямо в карточке; загрузка идёт дальше, даже если окно закрыть, и докачивается с того же места.
- **Поиск** — модели распознавания на Hugging Face. Показываются только те, что приложение узнаёт, со значком
  («подходит · sherpa-onnx», «подходит · whisper.cpp», «MLX · нужен движок», «не подходит: нет ONNX»), числом скачиваний,
  языками и лицензией; по умолчанию — только с русским. «Подробнее» читает репозиторий: тип модели, файлы, размер, коммит и
  предупреждение, если лицензия не указана или запрещает коммерческое использование. Если запускать нечего, окно скажет
  почему (например, «в репозитории нет ONNX-файлов — эта модель только для PyTorch») и предложит, что поискать.
- **На этом Mac** — модели, которые уже лежат на диске: кэш Hugging Face (`~/.cache/huggingface/hub`), папки whisper.cpp
  и `~/sherpa-onnx*`, или любая папка через «Выбрать папку…». Приложение их только читает: «Использовать на месте» ничего
  не копирует, а записывает описание в `models/external/`. Модель MLX будет найдена, но в этой сборке не запустится: окно
  скажет, чего не хватает, и предложит ту же модель для другого движка.
- **Мои модели** — всё, чем можно диктовать: основная, «Проверить» (распознаёт встроенную двухсекундную запись и
  показывает текст; проверка идёт в отдельном процессе, так что неподходящая модель не уронит приложение), «Удалить» для
  скачанных и «Убрать из списка» для подключённых с диска — их папка остаётся нетронутой.

Движки: **sherpa-onnx** (тип модели — трансдьюсер, CTC, Whisper, SenseVoice, Moonshine, Paraformer, FireRedASR, Dolphin,
Canary, T-one и другие — определяется по метаданным внутри ONNX-файлов), **whisper.cpp** (файлы `ggml-*.bin`, на видеокарте

## Устройство и функции сборки

- **Оболочка на Objective-C** (`MacApp/`): клавиша, запись звука, буфер обмена и вставка, строка меню, история.
- **Ядро на Rust** (`velikiy-moguchiy-core`, статическая библиотека `libvelikiy_moguchiy_core.a`, связь через C FFI):
  провайдеры распознавания (`velikiy-moguchiy-asr`), исправление LLM, настройки, модели, сборка итогового текста.
- **Swift-пакеты** `MLXBridge` и `AppleSpeechBridge`: мосты к MLX и к Apple SpeechAnalyzer через C FFI.

Локальные провайдеры включаются функциями Cargo в `velikiy-moguchiy-core/Cargo.toml`: `mlx`, `apple-speech`,
`sherpa-onnx` (по умолчанию все три) и `whisper-cpp`. `make build` и релизная сборка собирают ядро с
`--no-default-features --features apple-speech,sherpa-onnx,whisper-cpp` (`Makefile`, `MacApp/project.yml`): облачные
провайдеры, Apple Speech, sherpa-onnx и whisper.cpp (MLX пока не собирается на Xcode 26.3). whisper.cpp собирается из
исходников (нужен cmake) и линкуется статически, шейдеры Metal встроены в библиотеку. sherpa-onnx линкуется в варианте без синтеза речи (`scripts/sherpa-onnx-libs.sh`):
обычные библиотеки тянут в приложение espeak-ng под GPL-3.0. Функция `wetype-offline` никогда не входит ни в сборку
по умолчанию, ни в релиз.
